# 关于 v3.0 的签名体系

在传统的 Magisk ZIP 模块生态中，软件包的来源与完整性往往缺乏统一的验证机制，用户很难确认一个模块是否真正来自其声称的开发者，也难以判断它是否被第三方篡改

对于可能获得较高系统权限的模块而言，这类风险不容忽视：轻则导致个人资料泄露，重则破坏系统环境，甚至使设备无法正常启动

对此，我思考了很久：

**能否在尊重用户选择权的同时，为软件包建立一套更可靠的信任机制？**

这便是我对 Rootless Store v3.0 签名体系的设想

## 签名体系的选择

Rootless Store 计划引入基于数字签名与证书的信任体系，由官方提供默认信任根，并允许用户自主扩展信任范围

数字签名能够帮助验证软件包的签名来源及内容完整性，让签名后的篡改更容易被发现

但我们必须明确一点：**签名有效，并不意味着软件包绝对安全**

数字签名无法保证签名者没有恶意，也无法替代对软件包实际行为的安全审查

因此，我们希望与开发者及社区共同建立一套**来源可验证、内容可校验、信任可管理**的机制，而不是简单地给软件包贴上「安全」或「不安全」的标签

## 官方默认信任根与持续性的去中心化

为了让普通用户开箱即用，Rootless Store 将提供由官方维护的默认根证书，作为初始信任基础

符合验证规则、能够建立到受信任根证书的有效证书链的软件包，可以通过相应的签名校验

但**官方提供默认信任，不意味着官方必须垄断信任**

用户可以自行建立证书颁发机构（Certificate Authority，简称 CA），并将自己的根证书导入 App 的信任存储

开发者和社区组织同样可以公开自己的证书信息，由用户自行审查，并决定是否将其纳入信任范围

这种设计兼顾了易用性与自主权：

普通用户可以依靠官方提供的默认配置，获得基础的签名验证能力；而有更高自主性需求的用户，则可以根据自己的判断，建立或扩展独立的信任体系

我们并不希望 Rootless Store 成为信任的唯一裁决者

**Rootless Store 希望提供建立信任的工具，而不是垄断信任的权力**

这也是我们对去中心化理念的一贯追求

## 对于未签名软件包的赦免

新安全机制的引入，不应当意味着对既有生态的全盘否定

对于采用旧版打包方式、未经数字签名的软件包，我们并不推崇直接安装

但只要它符合 Rootless Store 所支持的 Package 格式要求，App 仍会尝试解析，并在安装前明确提示其未经签名验证所带来的风险

在充分了解风险后，用户仍可以自行选择是否继续安装

Rootless Store 也会尝试沿用原有流程，完成软件包的解析与安装

我们始终认为，**允许安装，不代表已经验证安全；提供警告，也不是替用户作出决定**

安全机制存在的意义，应当是帮助用户识别风险、理解风险，而不是在任何情况下都剥夺用户的选择权

我们希望让安全性与自由选择并存

**让信任有据可查，让风险清晰可见，也让最终的选择留在用户手中**
